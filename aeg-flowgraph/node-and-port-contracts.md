# AEG FlowGraph：节点与端口规范

[返回架构总览](<../AEG FlowGraph Architecture.md>)

端口字段、ValueSchema、来源状态和兼容矩阵以 [作者与执行契约](authoring-and-execution-contract.md) 为准；本分册展开 Frame/Render profile 的节点卡片、连接和图边界规格。Logic/Flow 的 State/Transition/Event/Action 只在总契约中定义，尚未纳入首期编辑交付。

## 1. 节点类型分层

节点库不是把 C++ 类或内部 Task 全部列出来，而是列出具备稳定作者契约的积木。每个类型需要有显示名、用途、图层适用范围、输入/输出端口、参数、默认值、能力和编译规则。

| 节点类别      | 作用                       | 示例                                     | 可否进入子图                     |
|---------------|----------------------------|------------------------------------------|----------------------------------|
| Pipeline（Frame/Render） | 根图或可复用流程容器       | Forward Pipeline、Mobile Pipeline        | 可，作为子 Pipeline/代理时需声明 |
| Feature       | 领域能力黑盒或子图         | Bloom、Outline、Audio Occlusion          | 可，双击进入 Feature 图；Logic Feature 的 Flow/State 子图另按 profile 处理 |
| Pass（Frame/Render） | 原子执行能力               | Extract Lights、Blur、Composite          | 只有 CompositePass 可展开；不得承载跨帧状态 |
| Resource      | 资源声明/外部资源/历史资源 | SceneColor、Depth、LightBuffer           | 可作为共享资源节点               |
| Value         | 值和参数来源               | Float、Color、Curve、Enum、Constant      | 可嵌套到任意兼容图               |
| Adapter       | 明确数据转换               | Resample、Format Convert、Color Space    | 可，转换成本可见                 |
| Merge/Compose | 多源合并                   | Blend、Layer Compose、Join、Select       | 可，必须声明合并语义             |
| Boundary（Frame/Render） | 图输入/输出和运行上下文    | Graph Input、Graph Output、Frame Context | 由图管理，部分可配置             |
| Debug         | 观察和采样                 | Debug View、Capture Resource             | 只改变观察，不改变主数据语义     |

## 2. 节点卡片结构

节点视觉从上到下固定为：

1. 类型图标、显示名、启用/只读/未知徽标。
2. 节点实例名和来源（内置、项目、资产、子图）。
3. 输入端口区：名称、类型色、连接数、必填标记。
4. 中间参数摘要：关键数值、展开按钮和诊断徽标。
5. 输出端口区：名称、类型色、连接数、资源/值/Token 图标。
6. 底部操作：进入子图、复制、删除、定位来源。

节点宽度根据端口名称和错误文本自适应；端口数量过多时允许折叠分组，但折叠组仍显示没有可用来源的必需数量。缩放到远景时保留类型图标、实例名和错误徽标。

## 3. 端口契约

节点类型的设计者定义输入输出契约；编辑器展示契约，图作者为已有端口选择数据来源。每个端口必须由类型定义下列字段，实例不能临时创建未声明的输入：

| 字段                                      | 说明                                             | 示例                                                                        |
|-------------------------------------------|--------------------------------------------------|-----------------------------------------------------------------------------|
| PortId                                    | 稳定端口身份                                     | `scene_color_in`                                                            |
| Direction                                 | Input 或 Output                                  | 输入                                                                        |
| DataType                                  | 数据值/资源/Artifact/Token                       | `Texture2D<Color>`                                                          |
| Domain                                    | 数据领域                                         | Render                                                                      |
| Scope                                     | 数据作用域                                       | Frame/View                                                                  |
| Access                                    | Read/Write/ReadWrite/Consume                     | Read                                                                        |
| ConnectionMode                            | 单来源或节点声明的可变来源组；不由拖线改变       | Single / Variadic                                                           |
| ConnectionCount                           | 允许连接的最小和最大数量；与来源模式分别校验     | 固定输入 1..1 或 0..1；可变组 2..4；无边但有合法 Asset 来源时不按边数量误报 |
| SourcePolicy（规范字段 `AllowedSources`） | 允许的来源模式；与连接数量分开定义               | EdgeOnly / AssetOnly / EdgeOrAsset / Context                                |
| BindingSchema                             | 外部绑定需要什么稳定身份和参数                   | AssetId、资源类别、格式约束                                                 |
| Required / Default                        | 执行前是否必须获得合法来源，以及无边时的默认行为 | 必需输入可由数据边、资产绑定或上下文满足；可选输入可使用声明的 1.0          |
| ElementCount                              | 数据本身为数组时的元素数量约束；不等于连线数     | 一根线传入 8 个元素的数组                                                   |
| SlotPolicy                                | 可变组的槽位身份、增删规则、排序语义             | 稳定槽位身份；最少 2 项、最多 4 项                                          |
| Format constraints                        | 格式、尺寸、采样、颜色空间                       | RGBA16F                                                                     |
| Lifetime                                  | 数据存活时间                                     | Transient                                                                   |
| Conversion                                | 允许的 Adapter 类型                              | Resample、FormatConvert                                                     |
| Exposure                                  | 是否可作为 Graph Input/Output                    | 可输出                                                                      |

端口显示名可本地化，但 PortId 不随显示名变化。节点复制、类型升级和资产迁移都依赖稳定身份。

一个节点有几个命名输入、每个输入要什么数据、是否可选、允许多少来源、允许文件/资产绑定还是只能接上游，以及如何处理这些来源，均由节点定义。未声明多来源的端口默认只允许一个来源；未声明外部绑定的端口不能在检查器里强行选择文件。缺少完整契约的节点显示“类型声明不完整”，不能由编辑器猜测接口。输入与输出的增删按钮不是每个节点的通用操作。

这里必须分开三个概念：

1. **端口是否存在**：由节点类型声明，例如 `SceneColor` 这个命名输入不能由画布临时创造。
2. **数据边允许几条**：由 `ConnectionCount`/Variadic 规则声明，例如最多一条上游边或允许 0..3 条层输入。
3. **执行前如何满足输入**：由 `SourcePolicy`（规范字段 `AllowedSources`）声明，例如必须接边、必须选资产、使用默认值，或在数据边与资产之间显式二选一。

因此，“没有前置节点输入”不等于“节点没有这个输入”，也不等于“输入缺失”。只有端口存在、来源模式允许且来源已解析时，节点才处于可执行状态。

### 3.1 无边输入与外部绑定

端口状态必须同时显示“数据边数量”和“来源满足状态”。例如：

| 状态     | 数据边 |     外部绑定 | 编译资格                                    |
|----------|-------:|-------------:|---------------------------------------------|
| 动态来源 |      1 |           无 | 就绪，B 等待上游 A 的结果                   |
| 静态资产 |      0 | 合法 AssetId | 就绪，等待资源 Prepare/Cook，不虚构上游节点 |
| 默认值   |      0 |   契约默认值 | 就绪，使用声明默认值                        |
| 缺失来源 |      0 |           无 | 错误，不能编译                              |
| 冲突来源 |      1 | 另有资产绑定 | 错误或要求用户明确切换来源模式              |

对 `Texture2D`、LUT、材质参数等固定资源，编辑器可以在端口检查器提供“选择资产”；对需要可见生产关系、可共享或可继续处理的资源，推荐使用独立 Resource/Texture Asset 节点并通过普通数据边连接。

## 4. 端口连接规则

连接提交前依次检查：

1. 源为 Output、目标为 Input；禁止 Input→Input、Output→Output。
2. 两端位于允许的图边界内；私有子图端口不可跨图直连。
3. Domain、DataType、Scope、Access 和 Lifetime 兼容。
4. 格式、尺寸、采样数、颜色空间和资源布局符合约束。
5. 当前端口属于节点声明，且当前签名及数量上限允许这条边；单来源端口已有连接时进入替换流程，不扩展输入。
6. 如果来源模式是 EdgeOnly 或当前选择了 Edge，建立数据来源绑定和 A 先于 B 的依赖；如果来源模式是 Asset/Default/Context，则验证外部绑定或上下文，不创建虚假的普通执行边。检查其与已有数据边、固定时序是否形成循环或破坏 History/External 协议。
7. 目标队列、阶段和同步要求能兑现 A 的结果就绪后 B 才开始执行；不能满足时拒绝连接，不降级成仅记录一个数据引用。
8. 连接后不会形成两个未声明的写入者或无法解释的资源别名。

连接失败时保留拖拽预览线，释放后不写入文档。错误消息优先说明修复方向，例如“需要 `Texture2D<Color>`，当前端口输出 `Texture2D<Depth>`；插入 Format/Material Adapter，或改接颜色输出”，不要只写“类型不匹配”。

## 5. 数据类型和端口颜色

颜色不是类型校验的替代品，而是快速识别方式。颜色和图标需要同时表达：

| 数据类别               | 建议视觉     | 示例                         |
|------------------------|--------------|------------------------------|
| Scalar/Bool/Enum       | 黄色         | Exposure、Quality、Enabled   |
| Vector/Color           | 青色         | Direction、Tint、UV          |
| Texture/RenderTarget   | 紫色         | SceneColor、BloomTexture     |
| Buffer/Structured Data | 蓝色         | LightList、InstanceBuffer    |
| Artifact/Snapshot      | 绿色         | WorldSnapshot、VisibleActors |
| ExecutionToken/Receipt | 橙色虚线     | Finished、WriteReceipt       |
| External/History       | 灰蓝色加徽标 | PreviousFrame、CameraInput   |
| Error/Unknown          | 红色/灰色    | 未知类型、端口丢失           |

深色模式下必须保证色盲可辨识，端口类型名和图标不能被隐藏。连线选中时加粗并显示 tooltip，错误线显示断点和错误编号。所有普通线型（包括声明的 Token/Receipt）均表示数据与先后，不能用不同颜色暗示“有些数据线没有执行依赖”。

## 6. 多输入端口规范

### 6.1 Named Inputs

多个语义不同的源由节点设计为多个命名端口。示例类型 `Bloom.Basic` 只声明 `SceneColor`、`BrightnessMask`、`Exposure` 三个输入，每个最多接一个来源；`SceneColor` 和 `BrightnessMask` 可以声明 `EdgeOrAsset`，因此可以接动态生产者，也可以在检查器中绑定合法纹理资产；`Exposure` 使用 `EdgeOrDefault`，未连线时使用声明默认值 1.0。实例不允许新增第四个输入，也不能因为某输入可选就删除它的定义。两个端口可以要求相同类型，但承担不同用途。

### 6.2 Variadic Inputs

只有节点设计者明确声明 Variadic 输入组时，编辑器才展示增减槽位能力。声明必须包括成员数据类型、最小/最大来源数、是否有序、缺失值/空集合行为和实际处理方法；不是接入任意数据的通用容器。

示例类型 `LayerCompose.Bounded` 声明 2..4 个颜色层。界面显示“已连接 3 / 最少 2 / 最多 4”，最多存在 4 个槽位，每个槽位只接一个来源；达到 4 个后不再创建新槽位。固定输入节点没有这个加号。删除一个来源后可以暂时低于下限并保存草稿，但编译报告缺少输入。槽位使用稳定身份，显示序号变化不改变其他连接。

类型声明了有序合成时，用户可调整槽位顺序；这个顺序只决定合成节点如何处理数据，不给来源 A、C 增加执行先后。A、C 都先于合成节点，两者之间无额外依赖时可由调度器安排。

### 6.3 数组数据与多个来源的区别

`Array<Texture>` 是数据类型：一根线就可以传递完整数组。Variadic 是连接规则：节点明确允许多个来源分别进入一个输入组。数组端口默认仍是单来源；要让多个数组或多个纹理分别接入，必须由节点额外声明。数组长度、来源数量和固定命名端口数量分别校验，不用同一个“多输入”开关混淆三者。

### 6.4 Aggregation Nodes

当多个来源需要计算、混合或选择时，目录推荐显式节点：

- `Merge`：等待所有来源，输出集合或合并资源。
- `Blend/Compose`：按权重、遮罩或颜色状态合成。
- `Join`：等待多个 Token 或结果，再产生一个完成信号。
- `Select/Switch`：根据 Enum/Bool 选择一条来源。
- `Gather`：按作用域收集多个同类 Artifact。

上述节点本身也有明确输入契约，名称叫 Merge 或 Join 不意味着接收任意类型或任意数量。用户只能连接到已声明的端口；普通 Single 端口不能自动升级成 Variadic。聚合节点有真实合并需求时使用；一个已声明多输入的节点会自然等待其所有已连接来源，无需额外插入 Join。

### 6.5 参数影响接口时的处理

只有类型声明了“模式/数量参数决定接口”的确定规则，实例才可配置该参数。改变模式时先展示新旧签名、会断开的边和新增必填输入；确认后一次事务更新参数、端口和诊断，可完整撤销。输入数据的实际数量不能在运行过程中偷偷改变画布端口。未声明该规则的参数只影响值，不改变输入定义。

## 7. Graph Input/Output 规范

每个子图在打开时都显示边界节点。子图接口编辑属于“设计这个节点的定义”；父图中使用这个节点属于“配置实例”。只有在拥有该子图定义编辑权限时才可进行以下接口编辑，父图实例检查器不开放任意端口增删：

- `Graph Input` 可以新增、重命名、设置默认值、设置类型、来源模式和是否必须有可用来源。
- `Graph Output` 可以新增多个输出，选择输出类型、用途和父图可见性。
- 必需的 `FrameContext`、`View`、`ExecutionToken` 等系统端口不能删除，但可以更换兼容绑定。
- 未连接的公开输出会被标记为“未产生结果”；如果图类型允许副作用，则要求有 Receipt/Token 输出。
- 父图节点的输入/输出端口由版本化子图接口生成；父图连线不能绕过边界。接口更新列出所有调用实例并走迁移流程，不只为某次拖线临时新增端口。

## 8. Pass 的原子与复合形态（仅 Frame/Render 投影）

### 8.1 原子 Pass（内部 RenderGraph 工作）

原子 Pass 只暴露输入、输出、参数和执行契约。用户不能进入内部算法图；可以删除或替换实例、连接公开端口和修改授权参数。

### 8.2 CompositePass（RenderGraph 子图，不是业务 Composite Feature）

CompositePass 是由子图实现的可复用 Pass。双击节点打开内部 Pass 图；父图只看到公开端口。对子图进行“Expose Input/Output”操作时，系统显示会影响所有调用实例的范围：修改接口是版本迁移，不是普通布局操作。

### 8.3 SideEffect Pass（Render/Frame 副作用）

写入外部目标、提交历史或触发捕获的 Pass 必须声明 `SideEffect`。它至少有一个 `WriteReceipt`、`ExecutionToken` 或导出资源输出，后继节点通过该结果建立依赖。没有结果的副作用 Pass 不能靠摆放位置保证执行。

## 9. 删除、复制和替换

### 9.1 删除

用户创建的节点可删除。删除动作显示：节点、出入边、受影响输出、孤立资源、父图暴露端口和运行目标影响。执行后留下真实断线；用户可以撤销，或使用“从断线端口创建适配器/新节点”修复。

固定边界节点、必需运行上下文节点和由子图接口管理的代理不能删除。它们显示锁定原因和替代配置入口。

### 9.2 复制

复制产生新 NodeId。内部数据边保留；指向外部资源的输入按“复用合法只读绑定 / 创建副本 / 保持未连接”三选一。输出不能自动覆盖旧生产者；若目标端口单值，系统让用户明确选择替换或创建资源。

### 9.3 替换类型

从一个节点拖入另一个兼容节点时提供“替换节点”操作，显示保留的参数、迁移的端口、断开的边和新增必填输入。替换是一个事务，可以撤销；普通拖动只移动布局，不能误触替换。

## 10. 节点库和推荐创建

节点库提供搜索、按数据类型过滤、按当前端口过滤、最近使用、项目节点、内置节点和不可用原因。用户从端口拖出时，目录自动显示“能接到这个端口的节点”；释放到空白处时显示“从该输出继续”的候选。候选项显示输入名称、用途、必填性和数量范围；不能仅因类型一致就向一个未声明槽位或已满的输入组推荐连线。

推荐创建不自动落地。`Create Node From Pin` 只是打开已过滤的候选；用户确认后才创建节点和连接。对于存在唯一安全 Adapter 的类型转换，可以显示一键插入，但仍在历史中记录 Adapter 节点。

## 11. 图布局数据

节点坐标、折叠、注释框、Reroute 点和局部视图属于图布局/作者视图数据，不参与执行语义。连接、缺失输入和断线草稿属于作者语义，会影响验证和运行资格。自动布局只按依赖和端口方向排版，不改变边、数组顺序或参数。

Reroute 节点只改变线的路径，不产生数据、不影响拓扑；在运行检查和编译计划中被折叠为原边。注释框可以标记设计意图，但不能替代端口说明或验证规则。
